# Lessons（同じミスを繰り返さないための記録）

## C++ソース(.cpp/.h)に追加するコメントは英語で書く
- **状況**: `DXRPipeline.cpp` に「加速構造」等の漢字コメントを追加したらビルドエラー（`currentChecksum`が定義されていない識別子、C2065）。
- **原因**: ファイルはUTF-8だが、MSVCがコードページ932(Shift-JIS)として解釈する。「構」(Shift-JIS 0x8D5C)など**2バイト目が0x5C(`\`)になる漢字**が行末付近にあると、行継続扱いで次行のコード（`uint64_t currentChecksum = ...`）がコメントに巻き込まれて消える。`warning C4819`（コードページ932で表示できない文字）が前兆サイン。
- **対策**: **ネイティブC++ソース(.cpp/.h)に新規追加するコメントは英語で書く**。既存の日本語コメントは壊れていなければ触らない。C#(.cs)やドキュメントは日本語でOK（UTF-8として正しく扱われる）。
- **適用範囲**: `src/RayTraceVS.DXEngine/` `src/RayTraceVS.Interop/` のネイティブコードを編集する全タスク。

## リファクタリングは検証基盤を先に作る
- **状況**: RayTraceVSのリファクタリングで、出力同一性を検証する手段（テスト・ヘッドレス出力）が当初なかった。
- **対策**: Phase 0でヘッドレスレンダリング＋ピクセル比較を実装してから本体に着手。各変更後に `.\tools\verify_render.ps1` で完全一致を確認。[[verification-workflow]]参照（メモリ）。
- **効果**: C#層は出力ピクセル完全一致、C++最適化も同一性を客観確認できた。
